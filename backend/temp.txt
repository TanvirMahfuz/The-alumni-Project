# Backend Error-Handling / Crash-Risk Audit (temp doc for Docker readiness)

Project: The-alumni-Project/backend
Entry files: backend/app/app.js (Express app), backend/index.js (bootstrap)
Audit date: 2026-11-22

--------------------------------------------------------------------
1. Framework / runtime facts that make "logic will crash" likely
--------------------------------------------------------------------
- Express version installed: 4.22.3 (package.json declares ^4.21.1).
  Express v4 does NOT catch rejected promises from async route handlers
  automatically - async errors must be caught manually or wrapped.
- Runtime: Node v24.14.0 - unhandled promise rejections terminate the
  process by default (crash).
- NO global Express error-handling middleware is registered anywhere
  (no `app.use((err, req, res, next) => ...)` in backend/app/app.js).
  Errors escaping handlers fall through to Express defaults / unhandled
  rejections.

--------------------------------------------------------------------
2. Logic that CRASHES the process (unhandled rejection -> no proper response)
--------------------------------------------------------------------

[2.1] PUT /api/v1/user/updateUser - async handler has NO try/catch
- File: backend/app/controllers/UserController/updateUser.js:5
- `export const updateUser = async (req, res) => { ... }` has no try/catch.
- Any throw escapes as rejected promise -> Express 4 ignores -> unhandled
  rejection -> Node 24 CRASH.
- Concrete throwers: backend/app/utility/updateValidation.js:117
  (Error "Invalid email format") and :121 (Error "Password must be at least 6 characters").
- Docker impact: container process dies, restarts, client gets no response.

[2.2] POST /api/v1/post/updatePost - missing return + catch re-send after headers sent
- File: backend/app/controllers/PostController/updatePostController.js:7-11 and :16-21
- `if (!post) { res.status(400).json({...}) }` missing `return` -> execution continues.
- Sends 200 after 400 was already sent -> ERR_HTTP_HEADERS_SENT thrown -> caught ->
  catch tries `res.status(500).json(...)` again -> throws again -> unhandled rejection -> CRASH.

[2.3] POST /api/v1/post/deletePost - same missing-return / double-send pattern
- File: backend/app/controllers/PostController/deletePostController.js:7-11 and :16-21
- Missing `return` after 400 response -> sends 200 after 400 -> headers already sent ->
  throws in catch -> catch re-sends 500 -> unhandled -> CRASH.

[2.4] POST /api/v1/post/deleteComments - missing return + undefined handler reference
- File: backend/app/controllers/PostController/deleteCommentsController.js:5-9, 10-13, 14-19
- Missing `return` before the 200 response after a 400 response.
- Calls `deleteComments(data)` which is not imported/defined in that module -> ReferenceError ->
  catch sends 500 (ok-ish) but the null-check flow still double-sends in the null path.
